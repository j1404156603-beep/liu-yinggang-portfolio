真实交付稿：车辆调度大屏。规范将复杂装饰资产与可编辑信息层分开记录。

01 / COLOR TOKENS

深色不是目的，
状态辨识才是

蓝黑色用于降低环境干扰，亮蓝建立交互边界，绿、黄、红只负责表达状态。以下关键值来自蓝湖精确标注与切图像素。

Canvas#081020大屏深色基底
Modal Surface#00093A五路视频弹窗
Primary Line#4794FF选中、边框、标题条
Modal Line#7EB0FF弹窗 2 px 内边框
Label#A8CBFF字段标签 14 px
Info#04A3FF关键实时数值
Success#36FF7D已连接、正常运行
Danger#FF5656停止、异常、危险
02 / TYPOGRAPHY

信息层与动作层，
使用不同的声音

信息文字保持稳定、清楚；关键动作与大屏标题使用更强的展示字体。模块装饰条可以保留切图，但内容文字应逐步改成可编辑文本。

04 / COMPONENTS

组件不只是外观，
还要说明状态与交付方式

以下组件来自实际切图。规范同时记录原始尺寸与后续工程化建议，避免继续用整块图片承载可编辑文字。

基础控制

166 × 34 px；2 px 边框；2 px 圆角。适用于选择器和基础动作。

成功动作

184 × 46 px；绿色只用于已确认、允许运行和成功状态。

危险动作

停止或异常状态。必须同时出现明确文案和二次确认。

状态灯

53 × 54 px；不能单独依赖颜色，应同时显示状态文字。

功能图标

切换 42 × 42；播放约 31 × 32；关闭 28 × 28。保留透明 PNG。

信息状态

用于当前模式和信息型选择，不与危险或成功状态混用。

06 / ASSET DELIVERY

区分装饰资产、
代码组件与状态数据

原始项目提供了完整 1×/2× 切图。作品集复盘进一步把它们转成可维护的工程交付规则。

KEEP AS ASSET

适合继续使用 PNG

  • 复杂发光与透明装饰框
  • 车辆、路侧设备与行人图形
  • 状态灯与复杂光晕
  • 无法稳定用 CSS 复现的纹理
  • 同时输出 Web @1x / @2x
BUILD IN CODE

应由代码实现

  • 正文、数值、状态与表格文字
  • 纯色背景、普通边框和圆角
  • 表格、列表、选择器和弹窗布局
  • 禁用、加载、悬停和聚焦状态
  • 对象选择与地图联动逻辑

证据边界：本页中的原始尺寸、字体、色值和版本日期来自用户当前打开的蓝湖项目；“8 px 网格、代码化文字、九宫格拉伸、无障碍状态”等属于作品集复盘后的交付规范，不冒充当时已经建立的正式设计系统。
